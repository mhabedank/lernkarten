## What the reviewer recomputed rather than took on trust

- **Demo corpus**: 4+3+2+5+10+7 = 31 cards. At 16 up: sheet 1 = 16, sheet 2 = 15 (rows 1–3 full, 3 cards in row 4). `divider_slot` = 44; records = 31 + 13 blanks + 4 dividers = 48; `pages(48)` = 6, `pages(31)` = 4. **SC-001 is correct.**
- **R1 algebra**: `W ≥ e − δ` (max 3) and `B ≥ δ − e` (max 3). **Correct, and the worst cases chosen were the right ones.** Note the visible band on the worst edge of the back face is only `4 − 2 − 1 = 1 mm`.
- **Bottom bleed**: divider bottom at `sheet-h − 5 + 1.5`, bleed to `sheet-h − 0.5 mm`. **Fits, with 0.5 mm to spare** at the default margin.
- **R3**: confirmed by reading `templates/cards.typ:54,59` against `:33-34,:42`. The research numbers are exactly what the code produces.
- **`sheet()`**: `cards.typ:71` is `place()` with no clip and page margin 0, so a `ch + 1.5 mm` box spills into the margin without disturbing anything. Painting order is enumeration order: crop marks first (`:66`), then cells 0..15.

## Findings

### 1. HIGH — Adjacent dividers overpaint each other's edge

`research.md:9-38` · `spec.md` FR-006 · `templates/cards.typ:67-72`

R1 derives `B ≥ 3` assuming what lies past the cut line is free to receive bleed. FR-004 makes that true for **cards** — but four dividers in one 4-column row share three vertical cut lines **with each other**, and divider n+1's bleed lands 3 mm inside divider n's face. Because `sheet()` paints in enumeration order, at perfect registration divider 1 carries a 3 mm yellow strip on its right edge, 2 a blue one, 3 a black one. On the mirrored back the same physical edge is overpainted by the same neighbour.

**No band geometry fixes this: two different colours cannot both bleed past one line.** Painting all bleeds under all faces removes the perfect-registration defect, but at δ = 2 mm the neighbour's colour still shows 2–3 mm on one face.

This is a decision, not an implementation detail:
(a) accept it and specify a neighbour-colour strip of up to `δ + e` on shared edges — and make T015 assert *the divider's own* colour, so the test exposes it honestly;
(b) separate dividers with a blank cell, forcing two rows and reopening the growth/crop-mark question for the upper row;
(c) give a divider-only sheet its own layout with a gutter.

**As written, T015 ("colour still reaches all four cut edges") would pass on the wrong colour.**

### 2. HIGH — SC-005 cannot be satisfied as stated

`spec.md:218` · `tasks.md:140` · `tests/test_e2e.py:429-430` · `scripts/build_pdf.py:518-529`

The existing suite already records that *"the engine stamps a CreationDate, so two builds of the same input already differ"*. The build passes no `--creation-timestamp` and sets no `SOURCE_DATE_EPOCH`, so **no byte comparison is possible today**. Worse, Phase 2 *deliberately changes the A8 bytes* (the crop marks move), yet SC-005 demands byte identity to "the previous release" at both grids. And no pre-feature artifact exists to compare against — the quickstart's `git stash` is not something pytest can do.

Re-baseline SC-005 to "identical to post-`fix/cropmarks-sheet-axis` main", add a reproducible-timestamp mechanism, and obtain the reference as a pinned SHA-256 per configuration in the style of `BOX_SHA256` (`tests/test_repo_hygiene.py:380`). T019's `cards.json` comparison is the part that is genuinely assertable now.

### 3. HIGH — The bleed paints over the crop marks the divider is cut to

`templates/cards.typ:48-72` · `plan.md:123` · no task

Crop marks are drawn first (`:66`), cells after. Bottom marks live at `y ∈ [sheet-h−5, sheet-h−2]` mm and side marks at `x ∈ [2, 5]`; the outer dividers' bleed covers `x ∈ [2, 8]` and `y` down to `sheet-h−0.5`. **Every mark touching the divider row is buried under the band.** And the divider's own bottom cut, 1.5 mm below the grid line, has no mark at all — the exact defect R3 says the prerequisite exists to prevent. `guide`-grey marks on a `#141414` band would be invisible regardless.

The plan's file tree promises "crop marks for the taller bottom row"; **no task delivers it.**

### 4. HIGH — Principle XI: five 🔴 tasks cannot fail on their assertion

`tasks.md:76-78, 80, 95, 107, 140`. The constitution is explicit: *"'Fails with ImportError' does not count as red; make it fail on the assertion."*

- **T015, T016, T017** run `--dividers` via subprocess before argparse knows the flag (T024/T026). They exit 2 with a usage error.
- **T023** has the same problem — unless T024 adds the flag, in which case **T026 is a duplicate**.
- **T029** asserts `check_project.py` never counts a divider. That script reads `cards/*.yaml` (`check_project.py:682-812`) and can never see a divider, which exists only in the build's in-memory record list. **Green by construction; proves nothing.**
- **T019 and T040** are regression guards, not behaviours: green before any code, never red. Label them as guards.

### 5. HIGH — `compartments: 4` at the default A7 grid is undefined

`spec.md` FR-009, FR-015 · `data-model.md:76-80`

A7 is the default grid. A user who answers "4" and then runs plain `lernkarten build cards/*.yaml` either has every build refused or has dividers silently dropped. **Neither is specified, and this is the first thing US2 hits in practice.**

### 6. HIGH — `lernkarten setup` is under-specified for implementation and for test

`contracts/cli.md:61-77` · FR-014b · `quickstart.md:74` · `tasks.md:121`

FR-014b says the error "MUST name the flags that set the same values non-interactively" — **no flag is named anywhere.** And the quickstart's own example `printf '4\nn\nn\n' | lernkarten setup` is a **pipe, not a terminal**, so by FR-014b it must be refused. The interactive happy path therefore has no pytest-reachable red test, and the only reachable path is the unspecified flag path.

### 7–15 (MEDIUM)

7. **`dividers_printed` never becomes true** (`data-model.md:65,:80`) — nothing flips it, so a project answering `4/no/no` gets four new dividers and a fresh `box.pdf` on every rebuild.
8. **Settings lookup root unspecified** — cwd or `project_root(card_file)`? `tests/test_e2e.py:46-50` runs with `cwd=ROOT`, so a developer's own gitignored file would change e2e results.
9. **Parallel group 2 same-file conflict** — T027 and T028 both edit `tests/test_e2e.py`.
10. **Margins in (0, 4.5) unspecified** — growth needs 1.5 mm and bleed 3 mm; `BLEED_MM = 3.0` as a constant contradicts "bounded above by `margin − GROWTH_MM`". At `--margin 1` the growth alone leaves the page. T013 tests only 5 and 0.
11. **How `divider.typ` receives the geometry is unspecified** — the record lists no geometry fields and R2 argues against widening `sys.inputs`, so either the template duplicates the numbers or the contract grows.
12. **US4 needs HTML link checking no task adds** — `check_docs.py:166-184` scans `markdown_files()` only; `docs/leitner.html` is invisible to it. Use `tests/test_landing_page.py:458`'s pattern instead.
13. **T024 hides most of the real work** — `payload()` (`LANGUAGES[c["language"]]` raises KeyError on a divider), `main_language()`, the `languages` set, `advise_about_ids()` (`c["id"]`), `offending_card()` and `page_count = pages(len(cards), grid)` **all assume every record is a card** (`build_pdf.py:451-466, 419-424, 400-416, 538-544, 713-724`). The cards list and the padded record list must stay separate.
14. **T047 puts a repo check in the wrong gate** — `check_project.py` validates a *user's project*; the repo's `skills/*/SKILL.md` are read by `check_docs.py:77-119`. The constitution's XI recipe is about what a skill *writes into a project*, which this change does not touch.
15. **Test placement** — T025 asserts exit codes in `test_build_pdf.py` ("unit, no typesetter", `docs/testing.md:111`); T043 asserts `check_docs.py` behaviour in `test_check_project.py` when `test_check_docs.py` exists.

### 16–17 (LOW)

16. **T006 is harder than it reads** — Typst FlateDecodes content streams. `pypdfium2` is already in `requirements-dev.txt`; rendering and sampling `guide`-coloured pixels near the page edge is the cheaper red test.
17. **Spec says "two questions"** at `spec.md:70` and `:181`, and `checklists/requirements.md:47` still says "two keys", against FR-013's three.

## Observations

- **Principle VI holds**, checked against the real imports: `build_pdf → cardid, engine, yamlio`; `cardid → yamlio`; `check_project → build_pdf, cardid, yamlio`; `check_docs → yamlio`; `figures → deps`. Adding `leitner` (leaf) and `settings → yamlio` introduces no cycle. **But the constitution's graph (`constitution.md:256-266`) and R2's copy of it omit `cardid` and `figures`** — T012 must be written against the real graph, not the documented one. Also `plan.md:117` calls `settings` a "LEAF over yamlio", which is a contradiction in terms.
- **R3 is correct and the separate-branch call is right.** Folding it in would let the feature's page-count tests pass while cards remain uncuttable.
- **FR-004 is sufficient for dividers against cards** on all four edges. The gap is dividers against *dividers* (finding 1).
- **Outer bleed on a real printer**: crop marks already assume printing from 2 mm in, so the growth strip (3.5–5 mm from the edge) is inside that assumption — but the bleed's last 1.5 mm (0.5–2 mm) is not. Worth a sentence in `docs/design.md`.
- **Padding cannot break page ordering.** `cards.typ:75-98` derives `sheets` from `cards.len()`; blanks are ordinary entries and mirroring applies to them alike.
- **`.gitignore`**: `lernkarten.yaml` with no slash matches at every level, as `sources.yaml` does; a fixture would need the same `!tests/fixtures/**/…` negation.
- **US2 acceptance 6** says *warning*; `quickstart.md` §2 still says *error* for `compartment: 4`.
