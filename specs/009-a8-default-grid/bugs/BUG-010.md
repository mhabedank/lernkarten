## Description

v0.9.0 moved the default grid from A7 to A8 — `scripts/build_pdf.py:59`,
`DEFAULT_GRID = GRIDS["4x4"]`. The constant moved. **Its description did not**,
except in four places someone happened to remember: `CLAUDE.md:68`,
`README.md:144`, `skills/print/SKILL.md:110` and the `--strict` advice at
`scripts/check_project.py:930-935` (FR-009).

Every other description of the default in this repository still says A7. The
issue names five sites. A sweep of the whole tree for "A7 is/means the default"
and for the A7 card dimensions stated as the default output finds **fourteen**,
in nine files. One is behavioural, one writes the wrong value into user data,
and the rest are prose — including two files that now contradict *themselves*.

### Verification

Every site below was read at the line cited, in the working tree at `4fc270c`
(v0.9.0). The five from the issue are confirmed at the lines it gives; nine more
are new here. The behavioural one was reproduced end to end (below), not
inferred from the source.

### 1. Behavioural — the A8 picture advisory is skipped for exactly the decks that print at A8

`scripts/check_project.py:990`:

```python
if build_pdf.parse_grid(data.get("grid") or "a7") == build_pdf.GRIDS["4x4"]:
    dense_with_pictures.append(where)
```

The advisory this feeds (`:1041` — *"pictures at A8 print about a third of the
area they get at A7 — legal, and worth a look before printing sixteen up"*) is
therefore never raised for a **grid-less** deck, which after v0.9.0 is the
common case and prints at A8. A deck that says `grid: a8` gets the warning; a
deck that says nothing, prints identically, and gets nothing.

Reproduced on a scratch project — one card, one `back_image`, everything else
held constant:

| deck | prints at | advisory |
|---|---|---|
| no `grid:` key | A8 | **none** |
| `grid: a8` | A8 | `WARNING: … pictures at A8 print about a third of the area …` |

The line predates the default move (`f7058d0`, *feat: /cards writes three kinds
of card from one figure*) and was not swept by `c9b07ee`.

**Correction (while implementing).** This report first said "no test covers this
advisory at all", from a grep for `dense_with_pictures` and the warning text.
Wrong: `test_an_a8_deck_with_pictures_is_noted_once` and
`test_an_a8_deck_without_pictures_is_not_noted` cover it. The real gap is
narrower and sharper — **both state `grid: a8` in the fixture**, so every test of
this advisory is of a deck that says which grid it wants, and none is of the
silent deck the default move created. That is why nothing went red.

### 2. `/cards` writes `grid: a7` into every new deck — the damaging one

`skills/cards/SKILL.md:173`, inside the schema block the skill hands the model:

```yaml
grid: a7                       # the card size these cards are written for
```

and `:186-190`, in the prose beside it:

> Always write `grid:` too, for the same reason … `a7` (2 x 4 per sheet,
> 105 x 74 mm) unless the user asks for A8; `a8` (4 x 4, 52.5 x 74 mm) halves
> the paper and halves the width every line has. Omitting the key still prints
> at A7, so nothing breaks

Three things are wrong here and they compound. The prose inverts the default.
The last sentence is flatly false since v0.9.0. And the schema block instructs
the model to **write a literal `grid: a7`**, so this is not a stale fallback
that a future move of `DEFAULT_GRID` corrects — every deck `/cards` produces is
*pinned* to the older, larger card, and `--grid a7`… `--grid a8` at print time
is the only way past it.

The consequence is exactly the two problems #84 existed to fix: that deck does
not fit `assets/card-box.pdf` (an A7 card is 100 mm wide against a 73 mm
opening) and `--dividers` refuses it. **The feature shipped a default whose own
generator overrides it.**

The dimensions in that prose are wrong independently of the default: `a8` is
74.25 × 52.5 mm landscape, not "52.5 x 74" — that is the portrait A8 that
BUG-007 removed, still quoted here.

## Root Cause Analysis

**A default has two halves and only one of them is a constant.** The other half
is its description, scattered across a prompt, a module docstring, a code
comment, a Typst header, a README, a landing page, a workflow doc and a manual
test matrix. Moving the constant is one line. Moving the description is fourteen
edits in nine files, and it was done by memory.

Three things had to hold for that to be safe, and none did:

1. **No requirement said the description had to move.** The spec named the
   documentation half twice — scope box and contract table — and wrote no FR
   for it. Under this project's own rule (*CLAUDE.md* § Repo rules, test-first;
   `docs/testing.md`), a skill change's red artifact is a check in
   `check_project.py` plus a failing test. With no FR there was no test, and
   with no test the change was invisible.
2. **No planning artifact enumerated the sites.** 009 has no `plan.md` and no
   `tasks.md`. The feature that *introduced* the key had both, and its T026
   fixed two of the exact sites that are stale again now.
3. **No gate checks a claim.** `scripts/check_docs.py` is green today: it
   checks links, skill frontmatter, the version triple, the Leitner intervals,
   the import graph, and two text claims. It does not check this one.

The third point is the interesting one, because **`check_docs.py` already
contains two gates of exactly the proposed shape, and the second one was born
from this exact failure.** `check_print_order`'s own comment, at
`scripts/check_docs.py:339-343`:

> Same shape as `check_sheet_capacity` above and there for the same reason: the
> `--grid` sweep was enforced by a hand-written grep, missed two lines, and
> shipped them.

That is this bug, one release earlier, about a different sentence. The pattern
has now recurred three times. It also matches the standing lesson recorded from
v0.4.0: *verify criteria as gates, not greps.*

## Recommended Fix

Test-first per *CLAUDE.md* § Repo rules. The red artifact differs by site,
because most of these files are not read by anything today.

1. **The behavioural one gets a real red test.** A grid-less deck carrying a
   picture must produce the dense-with-pictures advisory. Assert it absent-then-
   present in `tests/test_check_project.py` (which covers this advisory not at
   all today), then fix `check_project.py:990` to resolve through the constant
   rather than a literal — `data.get("grid") or build_pdf.DEFAULT_GRID`, in
   whatever spelling `parse_grid` accepts — so check and build cannot drift
   again. This is the arrangement FR-002 already forced on the *reference*
   grid: the two ideas of "which grid" are named once and never retyped.

2. **The descriptive ones get a gate in `scripts/check_docs.py`**: no file
   outside `specs/` may call A7 the default, or state the A7 card dimensions as
   what a default build produces. Precedent, shape and rationale are already in
   that file (`check_sheet_capacity`, `check_print_order`), and its own comment
   says why. **Two scope problems to solve in the patch:**
   - `markdown_files()` (`check_docs.py:167`) covers root `*.md`, `docs/*.md`
     and `skills/*/SKILL.md`. That reaches sites #2, #5, #6, #7, #8 and #14 —
     and misses #1, #3, #4 (`.py`), #9 (`.typ`) and #10–#13 (`.html`), which is
     **six of fourteen**. The gate needs a wider file set than the existing two
     use, or those six stay unguarded.
   - It must not fire on `specs/`, on `docs/design.md`'s deliberate
     explanation of why the *reference* stays A7, or on the historically
     correct A7-was-default text in 003-card-grid and 007-card-box.

3. **`skills/cards/SKILL.md:173` and `:186-190`** — schema block writes
   `grid: a8`; the prose inverts (`a8` unless the user asks for A7); *"omitting
   the key still prints at A7"* becomes A8. Fix the A8 dimensions in the same
   edit: `74.25 × 52.5 mm` landscape, not `52.5 x 74`.

4. **`scripts/build_pdf.py:4`** docstring, **`scripts/check_project.py:920`**
   comment, **`templates/cards.typ:10`** header.

5. **`README.md`** — `:155` (cut count), `:181-183` (default and borderless card
   dimensions), `:195` (the direct contradiction of `:144`).

6. **`docs/index.html`** — `:430` hero facts, `:676` cut sentence, `:680-690`
   SVG **and `aria-label`**, `:691` margin paragraph. The SVG is a drawing, so
   this is a design change, not a text edit: read `docs/design.md` first per
   Principle XVI, and check whether `tests/test_landing_page.py` should assert
   the cut count so the picture cannot drift from the default again.

7. **`docs/workflow.md:328`** and **`docs/testing.md:262`** — the latter needs a
   decision, not just an edit: whether steps 17–19 now walk A8 first.

8. **`tests/test_landing_page.py:505`** — the assertion message.

9. **Retrofit or supersede the 003-card-grid contract.**
   `contracts/cards-yaml-grid.md` states "absent means a7" three times as the
   live contract. At minimum a superseded-by note; the patch should decide.

## Open Questions

Carried from the issue, with what the investigation says about each.

- **Should `check_project.py` resolve an absent grid through `build_pdf` at
  all?** Reuse says one place owns the answer, and site #1 is what happens when
  it does not. Against: `check` reports on *one file* while the build resolves
  *across files* with `--grid` in play, so a shared helper may be the wrong
  shape. Note the narrow fix — one name instead of one literal — needs no
  helper and no shared resolution, and is what recommendation 1 proposes.

- **Should a deck `/cards` writes carry `grid:` at all**, now that absence means
  the good default? FR-006's once-per-run report exists to find A7 decks that
  never said so, and a fresh deck writing `grid: a8` is a *statement*, which is
  what `skills/cards/SKILL.md:186` argues for by analogy with `language:`. It
  is also the line that has to be edited the next time the default moves — and
  this bug is a record of what that costs.

- **DECIDED (patch, 2026-09-07): split gate.** `check_docs.py` widens to markdown + `scripts/*.py` + `templates/*.typ`; `tests/test_landing_page.py` covers `docs/index.html`, which it already parses and whose claims it already owns. Each owner reads files it already reads, and between them all fourteen sites are covered. Tasks T007–T011.

- **DECIDED (patch, 2026-09-07): release note only** for decks already pinned to `grid: a7`. No new check — reporting every `grid: a7` deck would nag every deliberate A7 deck, the demo corpus included. FR-014, SC-012, task T022.

- **DECIDED (patch, 2026-09-07): `/cards` writes `grid: a8`** rather than omitting the key. FR-006's report and the `--strict` advice both ask a silent deck to state its grid, so a generator that stayed silent would fight the checker this feature shipped. FR-010, task T005.

- **DECIDED (patch, 2026-09-07): no plan retrofit for 009.** `tasks.md` is created for the fix and carries the site list, so the enumeration is durable without doing archaeology on a shipped feature.

- **Is the `check_docs.py` gate worth it for fourteen sites?** The
  count answers the issue's version of this question, which assumed five. So
  does the precedent: this would be the **third** gate in that file, and the
  second one's comment already documents the sweep-by-hand failure. #84's whole
  premise is that a default outlives the reason it was chosen, so the
  description of a default is exactly the thing that goes stale unattended. The
  real open question is narrower: **what file set does it cover**, given six of
  the fourteen sites are outside `markdown_files()`.

- **Does 009 want a `tasks.md` retrofit?** The missing artifacts are the cause,
  and 003-card-grid's T026 is proof that the tasks phase catches precisely these
  sites. But regenerating a plan for a shipped feature is archaeology. A middle
  path: no retrofit of 009, and instead a `tasks.md` for **this fix** carrying
  the site list above, so the enumeration exists somewhere durable.

- **New, not in the issue: does this want a release note or a patch release?**
  A user who ran `/cards` since v0.9.0 has decks pinned to `grid: a7` and does
  not know it. Fixing the skill does not fix their files. Whether the fix ships
  with an instruction to check existing decks — or whether `lernkarten check`'s
  FR-006 report already covers it, which it does **not**, because those decks
  do state a grid — is a scope decision for the patch.
