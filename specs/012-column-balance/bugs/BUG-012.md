# Bug Report: Phase 0 records the discarded layout as the decision, and four artifacts carry figures never observed

**Type**: Spec gap (SC-002 named one column of a two-column section) with documentation drift as its consequence
**Severity**: Medium — nothing shipped is wrong. `research.md` R2 teaches a contributor the arrangement that failed, as though it were the answer.
**Feature**: 012-column-balance (`design/column-balance`)
**Reported**: 2026-09-08
**Found by**: `/speckit-bugfix-verify`, run after implementation
**Status**: Patched
**Patched**: 2026-09-08

## Description

The layout of section `03 print it, cut it` was corrected mid-implementation.
The correction reached `spec.md`. It reached none of the artifacts that feed
into `spec.md`, and one of those now records the discarded variant as the
decision.

**What was decided in Phase 0**: send the cutting diagram to the sheets column
and let it wrap onto a second row beneath the two sheet mock-ups.

**What that produced**: the left column filled to 595 px against the rules
column's 433 px. Both columns are drawn to the taller, so 161 px of dead space
appeared **under the three rules on the right**. The hole did not close; it
crossed the section.

**What shipped**: the diagram sits *beside* the two sheets — three pictures in
one row — and both columns close at 433 px from 1280 px up. Between 1080 px and
about 1180 px the row wraps and roughly 160 px is left under the rules. That
fallback is accepted and documented: closing it would mean squeezing the
diagram's caption below the 15 px reading floor, and the layout never shrinks
reading text to fit (constitution XVI).

**#1 is the one that matters.** `research.md` R2 is what a contributor opens to
learn *why* the diagram sits where it does. Its Decision, its Rationale and its
evidence are all the variant that was thrown away — and its **Alternatives
considered** list does not contain the arrangement that shipped. Someone reading
R2 today learns the failed layout as the reasoned answer, and finds the correct
one nowhere.

The 547/627 figures came from a browser prototype that dropped the diagram's
padding. Neither that arrangement nor those numbers ever existed on the page.

## Artifact Traceability

### spec.md

- **Affected user story**: User Story 2 — *Section 03 puts the pictures with the
  pictures* (P2).
- **Affected criterion**: **SC-002**. Its original wording was:

  > *"In section 03, the visible content of the sheets column fills its column
  > to within the column's own padding."*

- **Gap identified**: **it names one column of a two-column section.** That is
  the whole defect. A criterion phrased that way is satisfiable by moving the
  imbalance to the column it does not name, which is exactly what the Phase 0
  decision did. The measurement that reported 0 % was not wrong — it measured
  the column SC-002 named, and that column was full.
- **Already corrected**: SC-002 and SC-003 were rewritten during implementation
  to name both columns and to state the 1080–1180 px fallback. `spec.md` needs
  nothing further; it is listed here because it is where the root cause lived.
- **Not affected**: FR-004 says only *"The cutting diagram MUST render in the
  same column as the sheet mock-ups."* That is true of both arrangements, so the
  functional requirement never distinguished them. Worth noticing rather than
  fixing — FR-004 is about placement and SC-002 was supposed to be about
  proportion.

### plan.md

- **Affected sections**: none.
- **Impact**: none. `plan.md` summarises R2 in one table row (*"Third child of
  `.print__sheets`; its `flex: 1`, `justify-content` and padding were written
  for its old life and change with it"*) and never quotes a figure or names a
  row. It is accidentally correct — the shipped diagram *is* the third child of
  `.print__sheets`. Recorded so the patch does not touch it looking for damage.

### tasks.md

- **Affected tasks**: **T026** (`tasks.md:262`), the by-hand measurement row,
  marked `[X]`.
- **False completions**: none, and this is worth being precise about. T026 was
  genuinely performed and is what **found** the defect — the row above it, T028,
  is *"look at every boundary in `03`"*, and looking at the section is what
  revealed the hole on the right. T026's instruction carries the wrong target
  figures, but the work it names was done and done properly. It needs its
  numbers corrected, not reopening.
- **Missing tasks**: one, to correct the four artifacts. R2 needs more than a
  find-and-replace — see *Recommended Fix*.

## Root Cause Analysis

Two failures, one behind the other.

**The root cause is a criterion that named one side of a two-sided thing.**
SC-002 asked whether *the sheets column* was full. The section has two columns,
both drawn to the height of the taller, so "is this column full" cannot
distinguish closing a hole from moving it. Every subsequent step was consistent
with the criterion and wrong about the page: the Phase 0 decision optimised for
it, the prototype measured it, the implementation satisfied it, and the
automated measurement confirmed it at 0 %.

**The second failure is that the correction did not propagate.** When the layout
was fixed, `spec.md` was updated because that is where the wrong criterion was.
The four documents *upstream* of it — the research that chose the arrangement,
the model that drew it, the guide that validates it, the task that measures it —
were left describing the abandoned variant. Nothing in this repository links a
spec correction back to the artifacts that produced the spec, so the update went
in the direction attention was already pointing.

This is the same shape as the defect the feature itself exists to fix: a check
that looks at one side, passes, and leaves the other side unexamined.

**What worked**: the by-hand row. `docs/testing.md` row 47 now says *"check the
right-hand one too"* for exactly this reason. Constitution XI's requirement that
manual claims be named — rather than left to a reviewer's eye — is what made
that row exist to be walked.

## Recommended Fix

1. Run `/speckit-bugfix-patch` to update the artifacts:
   - **`research.md` R2 — rewrite, do not find-and-replace.** Keep the wrapped
     variant as a **rejected alternative with its measurement** (595 px left
     against 433 px right, 161 px dead under the rules). It is the most useful
     thing this feature learned, and deleting it would leave the next
     contributor free to re-derive it. Then state the shipped decision — three
     pictures in one row, both columns closing at 433 px — with the 1080–1180 px
     fallback and why it is accepted rather than forced.
   - **`quickstart.md:78`, `data-model.md:88`, `tasks.md:262`** — correct the
     figures to 433 px. `data-model.md`'s tree structure is already right and
     must not be redrawn.
   - **No task is reopened.** T026 was performed and found the defect.
2. Run `/speckit-bugfix-verify` to confirm the artifacts agree with each other
   and with the shipped page.
3. **No code change.** `docs/index.html`, `tests/test_landing_page.py`,
   `docs/design.md` and `docs/testing.md` all describe the shipped arrangement
   correctly and all gates are green. `/speckit-implement` is not needed.
