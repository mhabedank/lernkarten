# Bug Report: The card markup contract never says how to bold, and a `\` line break directly before `*` silently stops being one

**Type**: Spec gap
**Severity**: High
**Feature**: 001-goal-driven-catalog (see *Feature attribution* below — the
active bugfix context is `002-landing-page-fixes`, which does not own these
artifacts)
**Reported**: 2026-08-19
**GitHub issue**: [#31](https://github.com/mhabedank/lernkarten/issues/31)

## Description

While generating cards, the model writing them hit two Typst markup rules that
no artifact in this repo states, noticed them only because the build broke, and
reported them back to the user afterwards:

> "Zwei technische Punkte, die beim ersten Build hochkamen und die ich behoben
> habe: Typst nutzt einfache `*` für Fettschrift, nicht `**`, und nach dem
> Zeilenumbruch `\` wird ein direkt folgendes `*` als escaptes Sternchen
> gelesen. Beides ist jetzt korrigiert, falls du eigene Karten dazuschreibst."

Two separate defects live in that sentence:

1. **Bold is undocumented.** `CLAUDE.md:47-52`, `skills/cards/SKILL.md:106-111`
   and `docs/workflow.md:237-238` all describe maths, line breaks, bullets,
   quoting and escaping — and never say how to emphasise a word. A model
   trained on markdown fills the hole with `**bold**`, which Typst reads as two
   *empty* strong elements around plain text. The card prints unemphasised and
   nothing complains.
2. **`\` is only a line break before whitespace.** The same three places say a
   backslash is a line break, full stop. In Typst a backslash before a markup
   character is an *escape* of that character. In a one-line YAML string —
   which is what every card is — `'first\*bold* rest'` therefore yields a
   literal `*`, no line break, and every following `*` shifted by one.

## Evidence

Reproduced against the engine this repo pins (typst 0.15.1,
`~/.cache/lernkarten/engine/0.15.1/typst`).

**1 — `**` is not bold, and passes every gate:**

```
$ typst query … 'repr([**bold**])'
"sequence(strong(body: []), [bold], strong(body: []))"
warning: no text within stars
  = hint: using multiple consecutive stars (e.g. **) has no additional effect
```

```yaml
# /tmp/t1.yaml
back: 'This is **bold** in markdown.'
```

```
$ lernkarten check /tmp/t1.yaml
OK: 1 cards valid (english), test build succeeded (2 pages).
```

Exit code 0. The typesetter's warning never reaches the user — `build_pdf.py`
reads `result.stderr` only on failure (`scripts/build_pdf.py:167-171`). A deck
full of unbolded "bold" text passes `lernkarten check`, passes CI, and goes to
print.

**2 — `\` before `*` is an escape:**

```
$ typst … 'repr([line\*bold* rest])'
error: unclosed delimiter
```

```yaml
back: 'First line\*bold* rest of it.'
```

```
$ lernkarten check /tmp/lktest/t.yaml
The typesetter rejected the cards:
  unclosed delimiter
  Offending card: t-2 — Markup test / Break
```

The build *does* fail here, and it names the card — but "unclosed delimiter"
does not say that the backslash ate the star. With an even number of remaining
stars there is no error at all and the wrong span is bolded.

The working form separates them: `line\ *bold*` evaluates to
`sequence([line], linebreak(), [ ], strong(body: [bold]))` — line break intact,
bold intact. Note the `[ ]`: the separating space survives into the new line,
which the patch has to decide about (leading space, or a different separator).

## Root Cause Analysis

A **spec oversight**, twice, with the same shape: the markup contract was
written as a list of the things that had come up so far, not derived from
Typst's syntax. Emphasis had not come up, so it is absent. The backslash had
come up only in its line-break role, so it is stated in that role alone. Both
passages read as complete, which is why three separate documentation tasks
edited around them without noticing.

The reason it survived to a user is the deterministic half: `lernkarten check`
validates the YAML schema and then test-builds, so it catches whatever Typst
*rejects* and nothing Typst *accepts*. `**bold**` is accepted. The only signal
is a Typst warning, and warnings are discarded on the success path
(`scripts/build_pdf.py:167-171`) — the same "worse than a loud failure" pattern
as issue #24.

Aggravating: the model in this session recovered on its own and told the user in
passing. A less attentive run ships a deck of silently unemphasised cards.

## Recommended Fix

1. Run `/speckit.bugfix.patch` to add the emphasis rule and the backslash
   precondition to the card format contract, and a requirement that the
   deterministic half catch both.
2. Run `/speckit.bugfix.verify` to confirm consistency across spec, plan and
   tasks.
3. Resume `/speckit.implement` — red check first (`scripts/check_project.py` +
   `tests/test_check_project.py`), then the three prose files, then the demo
   card.

Open for the patch, not decided here:

- whether surfacing Typst's warnings on the success path is part of this fix or
  its own issue — it would have caught the `**` case generically
- whether `\ *bold*` (backslash, space, star) is the recommended form, given the
  space that survives into the new line, or whether the guidance should be to
  reorder so no markup character follows the break
