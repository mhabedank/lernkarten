# Bug Report: `/ingest` never says where it wrote, and the skill relies on an implicit working directory

**Type**: Spec gap (the reported defect is already fixed; what remains is the
part of it that was never specified)
**Severity**: Medium — no longer loses the ingest, still leaves the user unable
to see where it went
**Feature**: 001-goal-driven-catalog (see *Feature attribution* in
[BUG-002](BUG-002.md#feature-attribution) — same code, same reason)
**Reported**: 2026-08-19
**Status**: Patched
**Patched**: 2026-08-19
**GitHub issue**: [#11](https://github.com/mhabedank/lernkarten/issues/11)

## Description

The issue reports that `scripts/zotero_ingest.py` derives its output root from
its own location:

```python
ROOT = Path(__file__).resolve().parent.parent  # quoted as scripts/zotero_ingest.py:27
target = ROOT / "knowledge" / args.source_id  # quoted as scripts/zotero_ingest.py:130
```

so an `/ingest` run from the plugin cache writes into
`<plugin-cache>/knowledge/<id>/` and the user's project stays empty.

**That code is gone.** `51f0434` replaced it with a `--project` argument
defaulting to the current directory:

```python
# scripts/zotero_ingest.py:151
target = Path(args.project).expanduser() / "knowledge" / args.source_id
```

`51f0434` is an ancestor of `main`, so the reported failure does not reproduce on
any released version. The issue is nonetheless still open and still correct
about two of the four things it asks for, and those two are what this report
carries forward.

## What still holds

1. **The skill does not pass the project explicitly.**
   `skills/ingest/SKILL.md:40-41` invokes
   `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/zotero_ingest.py --source-id <id>`
   and the prose beside it says the script "writes into `knowledge/<id>/` of the
   current folder; `--project` says otherwise". The correct destination is
   therefore reached by *the working directory happening to be right* — the same
   implicit coupling the original bug was made of, one layer up. The issue asks
   for the argument to be passed rather than assumed, and it has not been.
2. **The summary never names the directory.** The run ends with

   ```
   Done: 3 new, 1 awaiting the Read tool, 14 skipped, 0 without a PDF
                                                # scripts/zotero_ingest.py:204-207
   ```

   which is true of every possible destination. The issue's fourth bullet —
   "print the resolved absolute target directory in the summary output, so a
   wrong location is visible immediately" — is the cheap check that would have
   turned the original bug from invisible into obvious, and it is exactly the
   part that was never done. It also happens to be the diagnostic
   [BUG-002](BUG-002.md) wants next to its `collisions` count.

## Root Cause Analysis

**Implementation error, then a partial repair.** The original defect was a real
mistake in the script. It was fixed in passing by `51f0434`, a commit about
end-to-end test data — the argument was added because the *test* needed to write
somewhere else, not because the bug was being closed. So the fix landed without
the report, without the explicit call site, and without the issue being closed;
nobody checked the issue against the code afterwards.

That is the actual defect worth recording: a bug fixed as a side effect of
unrelated work stays open in every artifact that tracks it, and the half of it
that only a deliberate fix would have covered — telling the user where the files
went — is still missing a year of runs later.

Open for the patch, not decided here:

- whether `--knowledge-root` should exist as a separate argument, as the issue
  suggests, or whether `--project` covers it. `--project` is the shape the rest

  second overlapping argument is a way to get them out of step

  end, where it would be visible before anything is written
